# Listing 资料接收与标准化

这是内部资料模块。仅完成资料读取、字段映射、标准化和下游交接，不依赖旧版 Listing 技能或其数据契约。目标交付范围是标题、5 点描述、长描述、ST；本模块不直接生成这些文案。

## 接收方式

按用户实际提供的文件工作，不要求四类资料一次交齐，不要求用户先重排表格。读取表格文件时使用当前环境可用的表格技能和工具。

先读取文件的工作表清单和表头，再确定映射。表名及表序是定位线索，实际字段用于验证；不能仅凭表序误读数据。下列示例表名不是固定名称。多表同时符合、关键字段不明确时，记录候选与差异，只询问影响下一步处理的部分。

每个来源记录文件名、文件版本或哈希、工作表、原始行号和字段名。无法取得的日期、站点、版本信息保留为空，不从文件名猜成已确认事实。保留原表内容，清洗结果单独保存。

## 一、关键词库：卖家精灵导出

### 原关键词

优先定位第一张表，例如 `US-B0946HTB6B(20)__`，核对以下字段：

| 原字段 | 标准字段 | 使用方法 |
| --- | --- | --- |
| 关键词 | raw / normalized | 原关键词文本及单独保存的归一化值 |
| 相关性 | relevance_raw / relevance / relevance_rank | 关键词优先级的第一依据 |
| 月搜索量 | volume_raw / monthly_search_volume | 同一相关性等级内，按月搜索量降序排列 |

相关性等级从高到低，rank 越小越优先：

1. 绝对精准
2. 相对精准
3. 一般相关
4. 泛相关
5. 不相关
6. 未收录

相关性优先于搜索量；高搜索量不得跨等级提高排名。相同等级、相同搜索量时保留来源顺序。搜索量缺失排在同级有有效搜索量的记录之后，缺失值不作为 0。

保存全部等级，不在接收阶段删除低等级词。排序不等于采用：不相关词标记为不建议使用；未收录词保留该标签，交下游判断，不能直接解释成零搜索量或无关。泛相关词是否采用由下游结合本品事实决定。

### 关键词词根

优先定位第三张表，例如 `Unique Words`，核对以下字段：

| 原字段 | 标准字段 | 使用方法 |
| --- | --- | --- |
| 词语 | raw / normalized | 用于后续组词的原始词根 |
| 关键词性 | relevance_raw / relevance / relevance_rank | 使用与原关键词相同的六级优先顺序 |
| 属性 | attribute_raw | 保留用户标注，作为后续组词和语义判断的依据 |

“关键词性”在本项目中表示相关性等级，不解释为语法词性。“属性”不预设枚举，不擅自改写或补全。词根没有提供搜索量时保留为空，不从原关键词表推算或继承。原关键词和词根分别保存，词根组合不得伪装成原表中的现成关键词。

## 二、竞品库：卖家精灵导出

### 竞品内容

优先定位第一张表，例如 `US`，核对以下字段：

| 原字段 | 标准字段 | 使用方法 |
| --- | --- | --- |
| 竞品类型 | competitor_type_raw / competitor_type / competitor_rank | 筛选和参考优先级 |
| ASIN | asin_raw / asin | 标识竞品，关联来源，辅助去重 |
| 产品卖点 | bullets_raw | 提供五点描述的分析与写作参考 |
| 商品标题 | title_raw | 提供标题结构、表达和关键词使用参考 |

竞品类型从高到低：强对标竞品（1）＞对标竞品（2）＞竞品（3）＞空白（4）。空白是此字段明确支持的最低优先级，不删除。未识别的其他标签标记为待核对，不当成空白。

保留全部竞品及其等级，按上述顺序向下游提供参考。用户尚未规定只采用哪些等级或取前几条，不自行增加固定数量或筛选门槛。

“产品卖点”保留完整原文与原有分隔；若拆分各点，同时保留未拆分原文，不假设每条记录一定有五点。标题和卖点分别交给对应写作环节。竞品表达只提供参考，不能作为本品功能、尺寸、认证或其他属性的事实依据，也不能直接复制成稿。标题是否符合要求应由写作与校验环节按目标站点、类目及已确认规则判断。

### 品牌名单

优先定位第二张表，例如 `Brands`，读取“品牌”字段，保留所有非空品牌及来源，归一化后去重。

从产品信息表或用户明确说明中识别本次产品品牌，禁止从竞品标题猜测本品品牌。

- 当前本品品牌作为允许品牌记录。
- 品牌表中除当前本品品牌之外的品牌，全部进入排除名单，覆盖标题、五点描述、长描述和 ST。
- 不因某个竞品未被选用而丢弃其品牌排除记录。
- 本品品牌尚未明确时，保留完整品牌名单，品牌排除检查标记为待确定；可以继续整理其他资料，但不能宣称最终品牌检查通过。
- 品牌别名仅在资料或用户确认支持时建立；不能凭语义相近放行其他品牌。普通词与品牌同名的冲突保留原词并注明，不能静默放行。

下游还应检查成稿中的其他品牌名；Brands 表不是“所有可能品牌”的完整证明。

## 三、违规词库

默认来源为本技能根目录的 [敏感词-词库.xlsx](../敏感词-词库.xlsx)，路径相对于技能目录解析，不依赖当前工作目录。每次生成、修改或检查文案前确认已经读取当前版本，不要求用户重新上传。续接时仅在文件哈希未变且标准化清单完整时复用已读取结果；词库有更新则重新读取并检查受影响的文案。

- 内置文件包含“售后类”和“销售类”两个工作表，均读取。表头为“关键词”和“翻译”：读取“关键词”列全部非空数据单元格作为禁用词；“翻译”列仅作为解释保留，不自动扩大为另一套禁用词。不得把这份文件误当作商品 SEO 关键词库，也不把表头、说明或空行纳入禁词。
- 用户补充的违规词库按实际表头映射：接受“违规词”“敏感词”“禁用词”或已明确为禁用词表的“关键词”列。只读取对应列，不能将整张表的所有非空单元格都当禁词。字段含义不明时记录待确认，不猜测。
- 默认将内置词库与用户补充词库取并集，再结合品牌排除规则使用。按 Unicode NFKC、大小写及连续空白归一化去重，保留原词、翻译、文件哈希、工作表和行号等全部来源。只有用户明确要求替换词库、停用某来源或允许某词时才调整本次有效规则，并记录范围；不改写原始词库。
- 向下游交付完整 `forbidden_terms`、来源版本、每个工作表的有效词条数、去重后总数及加载状态。只展示摘要，不在聊天中倾倒整份词库。

有效清单中的词语不得出现在本次交付的主标题、副标题、五点内部标题及正文、长描述、QA、ST 等商品文案中；单字段任务检查本次字段即可。生成时避用，交付前逐字段扫描，命中后修改并复查。不能因搜索量高、来自竞品或属于本品品牌而自动豁免。这是用户提供的禁用规则，不据此声称每个词都是亚马逊全站官方禁词。

匹配沿用总控规则：忽略大小写、Unicode 兼容形式和连续空白差异；拉丁词使用词边界，中文等连续文本的子串命中人工核对。不擅自扩充同义词或词形，不通过拆写规避检查。实际命中记录字段、词语、位置和来源；内部原文证据不混入商品发布稿。

内置文件缺失、不可读、没有有效词条或表头异常时，明确报告加载失败及原因；可继续处理不依赖该词库的资料或暂拟文案，但不得声称已完成禁词检查或整套文案通过。没有用户补充词库不代表内置词库缺失。仅在用户明确授权使用替代来源时按记录的替代范围检查。

## 四、产品信息表

读取所有工作表和全部产品数据，包括说明、单位、备注、变体、品牌、限制条件及可读取的图片文字等信息，不只抽取固定几列。记录无法读取的嵌入对象、图片或公式结果，不将“未读取到”写成“没有”。

同时保留完整原始数据与提取后的事实表。每条事实包含属性、值、单位、适用型号或变体、来源及确认状态。可追溯且适用范围明确的本品资料可以标记为有来源支持；含糊、相互冲突或依赖未提供材料的声明保持待核对。无法分类的数据保留在未映射项中，不丢弃。

本品品牌、型号或变体冲突时分别保留，不能合并成一个产品。关键词和竞品资料不能补成本品事实；产品表中的内容也不能免除最终的违规词与品牌检查。

## 标准化与冲突处理

- 原文不覆盖。匹配用文本可做 Unicode NFKC、首尾空白移除、连续空白合并及大小写归一化；不擅自做同义词合并、词干化或单复数合并。
- 表头可去除首尾空白。其他表头别名须由实际文件证据或用户说明支持，不能把“关键词性”与“属性”混为一列。
- 关键词与词根按各自记录类型、语言及归一化文本识别重复；保留各行来源和标签。同词的相关性、属性或搜索量不一致时保留候选值，标记冲突，不静默取最高等级或最大值，也不累加搜索量。
- 竞品按已知站点、ASIN 及变体识别重复；缺失标识时保留独立输入编号，不误合并。不同日期或版本保留来源。重复记录内容冲突时并列留存，不静默选有利版本。
- 空白、未收录、不相关、未知标签是不同状态。关键词和词根的空白或未知等级设 rank 为 null，进入待核对列表，不自动变为未收录。
- 搜索量保留原值。明确的数值及千位分隔可以解析；带单位、区间或缩写时仅在格式含义明确后换算，否则保持待核对。不同站点、时间范围的搜索量不直接混排。
- 来源表名可以作为站点识别线索；站点、语言和类目未确认时记录不确定性，不静默默认美国站或美式英语。

## 保存与下游交接

使用用户指定项目目录；未指定时，在当前工作区 `work/amazon-listing/<project-id>/` 保存中间资料。不同产品、站点、变体保持可区分。分批接收时登记新来源并更新受影响的数据，不覆盖原始文件，不要求用户重发已收到的内容。

标准化结果至少包含以下分区，可以保存在一个 JSON 中，无需为了格式拆成大量文件：

| 分区 | 内容 |
| --- | --- |
| project | 产品、当前品牌、站点、类目、语言、变体，以及待确认项 |
| sources | 文件、工作表、原始行列、版本或哈希、可知日期 |
| keywords | 原关键词、相关性、等级、月搜索量、来源、冲突和使用标记 |
| roots | 词语、关键词性、等级、属性、来源和冲突 |
| competitors | 竞品类型、等级、ASIN、产品卖点原文、商品标题原文及来源 |
| brand_rules | 原始品牌名单、允许品牌、排除品牌、待核对别名与冲突 |
| forbidden_terms | 完整违规词清单及来源 |
| product_data / facts | 完整产品数据及可追溯事实 |
| issues / readiness | 缺失、重复、冲突、未映射项和各环节就绪情况 |

每条标准化记录都保留唯一 ID 与来源引用。数据冲突必须以状态明确暴露给下游，不能只写在一段容易遗漏的说明里。

接收完成后向用户简要报告：四类资料分别收到什么、命中了哪些工作表和字段、有效记录数量、关键缺失或冲突，以及现在哪些分析可开始。不在资料接收报告中声称文案已生成或最终复查已通过。

下游用途固定为：原关键词和词根供关键词规划与组词；竞品卖点供五点参考；竞品标题供标题参考；产品信息供所有文案的事实依据；品牌排除名单及违规词库供本次所有商品文案字段的复查。本包的写作、复查与总入口按这一约定衔接。

## 产品变体表路由

产品表含父体SKU、MSKU及属性/属性单位时，衔接[变体资料读取](../../amazon-variant-planning/SKILL.md)，保留重复表头的物理列位置。属性1、相邻属性单位、属性2、相邻属性单位逐对读取，不能把后一单位覆盖前一单位。型号后缀仅作冲突检查，用户明确修正另记来源；不从后缀生成产品尺寸。

按父体SKU+MSKU核对重复，完全一致才合并并保留全部来源；不一致并列存储待核实。商品净重、含包装重量、产品结构尺寸、包装尺寸分别记录，缺失不推算。价格保留币种与来源。变体阶段输出真实属性轴、组合及可展示资料，不自动创建后台变体关系。

用户称为示例或未来模板的表格独立保存，不迁移成当前另一产品的事实。最新明确用户更正优先：例如将SKU的-5Y改成-1Y后可能形成重复行，应重新去重而非保留虚构5码选项。
