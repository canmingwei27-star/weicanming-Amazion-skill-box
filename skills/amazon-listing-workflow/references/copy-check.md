# 本地计数与标题来源检查

运行 python scripts/check_copy.py <draft.json>。成功返回0，机械约束失败返回1，输入格式错误返回2。可只提交本次修改的非空分区，不得省略必交但缺失的分区来伪装整套通过。

title对象字段：

- main、subtitle：实际单行文字。
- prefix：brand、quantity、total_length、color四个已确认事实字符串。
- core_keyword：实际选用的库内精准短语，必须紧随固定前缀。
- roots：实际完整有效词根目录，字符串数组。
- platform_main_limit、platform_subtitle_limit：已核实的平台限额；未核实为null。
- capacity_reason：主标题不足75时解释无法继续加入完整适用词根的原因。

bullets和qas沿用 [运行约定](run-contract.md)：完整五点为5项，完整QA为10项；部分稿如实报告缺口。

## 标题验收

- 主标题含空格≤75字符，填充目标75；副标题含空格严格大于110且小于125，即111–124字符；110、125均不合格。旧的不含空格65上限已取消；去空格数仅作辅助指标。
- 主标题从品牌开始，严格按prefix的品牌、数量、总长度、颜色拼接，然后紧接core_keyword。
- roots来自真实完整词根表，不能从候选标题倒推补词。词根是否适用、原等级、禁词、来源行号仍由工作流核对。
- 唯一库外例外是主标题prefix的四个事实字段。对前缀之后的全部主标题及完整副标题检查词根覆盖：主标题可豁免空格和分隔标点，副标题仅允许字母/数字及单个普通空格，不豁免形容词、连接词、数字或单位。
- 必须匹配完整词根，不能从一个多词词根中擅自拆出一部分作为授权。大小写/NFKC/空白归一化仅用于匹配，不将新词形自动视为库内词。
- 两段必须单行且使用单个普通空格。词根在两段合计最多两次；词形关系及平台重复单词另人工复核。
- 少于75时产生未填满提示，需在title.capacity_reason说明不能继续加入完整适用词根的原因。脚本不解决语义约束下的组合最优化，也不以补空格实现75。
- 平台限额只有核实后填入；不填仍核对用户主标题≤75及副标题111–124限制，但平台状态为未验证。

## 五点提纲检查

提交bullets时必须一并提交bullet_outline，详见运行约定。检查5行提纲、point_id顺序、主题topic_id唯一、主要claim_ids跨点不重复；每点focus、buyer_question、fact_ids、root_ids必填，成稿的point_id/topic_id/claim_ids必须匹配对应提纲。场景埋词记录在embedding_plan，计划词根与实际命中另核对。

主题与主张ID不是语义证明。相同尺寸主题换不同ID仍不合格，需要人工并排检查五点主旨。重复引用支持事实不等于主要主张重复，不能禁止所有fact_id跨点出现。

## 其余分区

字符数按Python len统计，包含空格、标点。五点实际计数包含内部标题，不包含外部列表编号；text须以完整body结尾，body最后不能为标点。150/150/400/400/400是软目标，不自动变成硬限制。

QA要求10条完整候选，Q≤100、A≤250，均含空格。qas_delivery_mode为review_candidates或verified；每题有source_refs和evidence_status。confirmed要求fact_ids；inferred/unconfirmed要求review_note并在交付中逐条可见。前者允许未确认候选通过机械检查，后者拒绝未确认答案。工具不判断事实真实性、题间语义重复或词根语义适配；副标题无需通过连贯短语检查。

mechanical_passed仅代表已实现的计数、标题顺序、词根字面来源与重复约束通过；不能证明词根目录真实、产品事实成立、品牌禁词合格、语义优先级合适或平台必定接受。ST仍由ST模块单独检查。

## 内置词库检查

按 [资料接收规则](data-intake.md#三违规词库) 加载内置词库及用户补充词库，再检查本次交付的商品文案。记录加载状态、词库版本、有效词条数、被检查字段及命中与修正结果。`check_copy.py` 不读取 Excel 词库，运行它不能代替禁用词检查；内置词库加载失败或仍有未处理命中时，不得标记禁词检查通过。
