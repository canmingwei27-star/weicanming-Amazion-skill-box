# 亚马逊 Listing 一体化

本文件夹是完整的一体化 Skill，按需读取 references 内的规则模块，并使用 scripts 内的工具。用户要求整套生成时按依赖推进，要求单个环节时只执行该环节及其必要前置步骤，不扩大交付范围。

这里的“调用”是当前助手读取对应包内规则文件并按其要求执行、保存结果。它不是常驻后台进程，不自动创建新聊天、启动子 agent、发布商品或运行定时任务。

## 启动与继续

1. 读取 [运行与数据约定](references/run-contract.md)。沿用已有项目的产品、站点、类目、语言、变体、输入版本及用户确认，避免重复询问。新项目只询问影响下一步的缺失信息。
2. 根据明确请求设置 `mode` 为 plan 或 generate。用户要求生成成稿时设 generate，执行各文案模块时明确要求生成完整文案，不能只交提纲。
3. 核对下列包内文件路径是否存在。只在执行某阶段时读取它的完整指令和所需参考文件，不一次加载全部。
4. 接收分批资料，完成当前可独立推进的工作，报告具体待补字段。缺某份资料不阻塞与其无关的分析，缺事实也不能以竞品补齐。

## 固定路由

| 阶段 ID | 内部规则与路径 | 输入和输出 |
| --- | --- | --- |
| intake | [资料接收](references/data-intake.md) | 关键词库、竞品库、违规词库、产品信息表 → 标准化数据、来源与冲突 |
| variants | [变体资料读取](../amazon-variant-planning/SKILL.md) | 产品变体表 → variants.json、真实属性组合、商品与包装资料、逐MSKU事实 |
| competitor_bullets | [五点竞品分析](references/competitor-bullets.md) | 竞品产品卖点及本品事实 → 卖点、结构、潜在购买疑问和五点参考 |
| competitor_titles | [标题竞品分析](references/competitor-titles.md) | 竞品商品标题及本品事实 → 信息构成、结构和标题参考 |
| keywords | [关键词规划](references/keyword-plan.md) | 关键词/词根、本品事实、品牌/违规词及已有竞品结论 → 字段分配、排除与待确认项 |
| title | [标题规划](references/title-plan.md) | 标题参考、词根分配和本品事实 → 主标题、副标题/Item Highlights 或其规划 |
| bullets | [五点规划](references/bullet-plan.md) | 五点参考、词根分配和本品事实 → 5点描述或其规划 |
| description | [长描述规划](references/description-plan.md) | 当前标题、五点、竞品分析、本品事实和词根 → 长描述或其规划 |
| qas | [QA规划](references/qa-plan.md) | 关键词/词根或竞品五点、本品资料及当前文案 → 10条供人工筛选的完整QA候选或其规划 |
| st | [ST规划](references/st-plan.md) | 词根、当前已有文案、事实及禁用规则 → 按当前版本直接生成并输出 ST |
| image_plan | [产品图片策划](../amazon-image-planning/SKILL.md) | 当前标题、五点、长描述、已确认事实及变体 → 独立九图文本策划HTML及image-plan.json |
| final_check | 本总控的交付复查 | 最新成稿、事实、词库与规则 → 检查报告和可交付部分 |

两个竞品分析环节相互独立，标题和五点生成也相互独立；可以依次执行，不要求并发 agent。先完成可用竞品分析；五点必须结合竞品主题与词根属性先形成五行提纲，分配事实、精准词及场景词并全局去重，然后才写正文。标题按其独立流程生成，再写长描述，再检查已覆盖内容并生成补充 QA，随后基于当前已有文本直接生成并输出 ST，最后复查；不等待用户筛选或修改QA。

只有关键词时可先清洗并暂拟分配；缺竞品时可基于本品事实暂拟文案，但参考状态必须标明未完成。先前生成的临时结果在依赖补齐后应复核，不能因有文件就视为全部完成。没有现有 Listing 时也可从词库或竞品五点生成10条完整候选Q/A，记录未核对正文重叠，不把推断当已确认事实。

核心文案规则和工具保持在本文件夹内；仅新增路由明确衔接 amazon-variant-planning 与 amazon-image-planning 两个配套技能，不自动加载其他旧版独立 Listing 技能。变体资料在intake后、各文案生成前读取；图片策划在本次实际文案齐备后执行。新的完整Listing项目默认包含独立九图策划，继续旧项目时尊重既定交付范围；单字段任务不自动扩展。仅修改Skill时交付规则与模板，不重新生成当前Listing。

## 变体与图片策划衔接

- 读取表格的实际属性类型与单位，不把属性1/2固定解释为颜色/尺寸；重复“属性单位”按列位置配对。按父体SKU+MSKU识别子体，只有真实存在的组合才可选；相同记录合并并保留来源，冲突保留待核实。用户修正优先于SKU后缀推断。
- HTML原“选择颜色版本”改为“变体与商品资料”，显示当前MSKU的品牌、分类、父体、属性、实际规格、价格、包装长宽高、包装重量及单独的商品重量/净重。缺失显示未提供，包装重量不充当净重。选择变体后同步全部文案、译文、计数、复制内容及图片策划适用关系。
- 图片按1主图、2尺寸、3单一场景1、4单一场景2、5细节、6四宫格多应用/多场景、7合拍、8使用说明、9SKU特征图排列。SKU图允许裁切到辨识特征，不要求完整产品；合拍不能暗示单独销售的颜色一并包含。
- 图片策划独立HTML文件、独立标签页，以文本策划与中英上图文案交付；不嵌入Listing底部或同文件切换面板。各图引用当前文案/事实版本，未确认QA不能成为图片卖点或使用步骤。

## ST 执行与依赖

调用 `references/st-plan.md`，以执行时当前已有的标题、副标题、五点、长描述及QA为版本快照，完成当前范围去重后直接输出实际ST。QA尚待人工筛选、可能日后修改或某些文案尚未生成，均不作为等待条件；内部记录已参与及尚未提供的字段。若后续实际需要修改，再依据更新后的现有内容生成新版ST，保留旧版；不要用“QA选择或修改后应重新去重ST”替代本次结果，也不把这句话作为固定交付尾注。

包内 ST 模块可用后，将旧项目 st 的 needs_skill 状态按实际资料重新评估为 pending、ready 或 needs_input，不自动标为 done。确实缺少包内规则文件时才记 needs_skill；用户未要求 ST 时记 not_requested。

绝对精准词根先全量纳入候选，再对当前已生成部分统一去重，包括绝对精准；ST内也不重复。按绝对精准＞相对精准＞一般相关＞泛相关＞不相关＞未收录排序，单空格连接，目标约240字符，最多250字符（含空格）。不再采用旧标题公告及ST官方索引摘要/字节说明作为生成或验收依据。

## 共享确认与规则

产品信息表中明确、无冲突且适用于本次产品的数据可直接使用。商品发布稿中的新增本品主张须有确认依据。QA人工筛选候选是例外：可直接拟写未确认答案并逐条显著标记，交用户修改选择，不等待补全资料；不能冒充本品确认事实或移入其他发布字段。参考结构和语言组织无需逐项征求确认。

各内部模块负责自身细则，总控核对其衔接：

- 关键词先判断事实适配与禁用，再按绝对精准、相对精准、一般相关、泛相关、不相关、未收录排序；同级原关键词参考搜索量。不相关词不因排在列表内而获得使用资格。
- 五点先分五个不同主题，再分配竞品依据、事实和词根，最后成稿。尺寸/数量/长度集中一处，超出细节移到描述或规格表。场景词按属性参与选题并分配至相关点，不只放第五点；使用用户已标注/允许的常规场景。全五点主张去重，关键词可自然重复。150/150/400/400/400为软目标，正文末尾无标点。
- 主标题按品牌→数量→总长度→颜色→精准关键词→补充词根排序，以75字符（含空格）为目标及上限；副标题采用词根堆积，严格大于110且小于125字符（含空格，即111–124），禁止标点和符号；不要求组成连贯短语或完整句子。仅主标题四个固定前缀字段可来自本品资料，其余主标题文字及整个副标题必须取自词根库。逐词保留来源，词根在两段合计最多两次；细则见标题模块。
- 长描述尽量覆盖前四级适用词根，允许与上文重复，说明场景、人群、核心功能与参数利益。问答表达不能被宣传为保证 Alexa 推荐的公式。
- QA固定交10条完整人工筛选候选，Q≤100、A≤250字符，均含空格。从关键词/词根或竞品五点选题，未确认答案可直接拟写并逐条标明状态与待核实事项。优先新增问题，也可具体化已有信息，不以新增事实不足缩减数量。

更新用户规则时保存新版本，以最新明确指令为准。平台规则核实由相关内部模块执行，保存来源、核实日期、站点和类目；未核实不得宣称已满足全平台要求。

## 最终复查与返工

将生成模式的实际文本按运行约定写入 draft.json。运行包内的 [计数工具](scripts/check_copy.py)，只传入本次已生成的分区；记录部分稿的数量缺口，不能为让脚本通过而伪造文本或隐藏必交字段。长描述和 ST 的适用长度另检，计数工具不覆盖它们的完整要求。

在机械检查之外，必须对实际展示文字执行：

1. 事实追溯与确认检查：发布字段的规格、场景、人群、型号与限制都有依据；QA候选检查来源及confirmed/inferred/unconfirmed标记，不将未确认候选误判为已核实；竞品不作为本品证据。
2. 品牌和违规词检查：扫描主标题、副标题、五点内部标题及正文、长描述、QA、ST，以及本次实际生成的其他商品字段。使用完整排除名单与词库，不因筛选竞品缩减名单。内部原文证据与商品文案分开保存。
3. 覆盖与语义检查：分别记录精确词根、词形变化、仅语义覆盖及未用原因；QA选题独立并记录已有信息重叠，五点主题不重复，副标题按词根堆积、来源适用、111–124字符且无标点。
4. 规则检查：用户长度和格式要求、实际站点/类目的字段要求分别列明。未知状态、缺词库、缺品牌或未验证规则不能写成“通过”。ST另检250字符硬上限、约240字符目标、六级顺序、全等级去重及当前版本实际去重范围；QA待筛选不影响本次ST生成完成。
5. HTML双语交付检查：按 [HTML与中文翻译规则](references/html-delivery.md) 核对请求字段齐全、原文与中文逐项对应、翻译不新增事实；纯原文计数及ST去重不混入HTML标签、中文译文或说明。

6. 若本次含变体，逐MSKU核对资料与文案绑定、有效组合、原始单位、缺失状态及复制内容；若本次含图片策划，核对9张顺序、事实依据、中英文案、逐变体适用表和独立HTML交付。

词语匹配忽略大小写、Unicode 兼容形式和连续空白差异；拉丁词使用词边界以免误报词内片段，中文等连续文本的子串命中人工核对。已确认的词形/别名按记录检查，不私自扩充同义禁词，也不通过拆写规避。所有真实命中都需解决或从可交付稿移出，不能以“常用词”自动豁免用户禁词。

修复交由负责该字段的内部模块完成，然后重新检查受影响项目。标题或五点改动时复核长描述衔接；标题、五点、长描述改动时重检 QA 的新增信息；标题、副标题、五点、长描述或QA实际改动且本次需要更新ST时，按改后的当前版本生成并输出新版ST；尚未发生的修改不影响已交付版本。资料或要求缺失时交付已通过部分并列具体缺口，不无限改写或声称整套通过。

## 交付

Listing内容统一以可直接打开的HTML文件交付，并包含目标语言原文及对应中文翻译；读取 [HTML与中文翻译规则](references/html-delivery.md)。通常按主标题、副标题、五点、长描述、10条QA、ST顺序排列，只输出本次请求范围；单独生成标题或ST也适用。用户另行指定格式或顺序时遵从。规划模式用HTML呈现提纲及相关译文，不能把规划标为生成完成。仅修改Skill规则的请求不自动重写Listing。

附简短进度与复查结果：本次完成字段、实际计数、待确认/缺失模块、未用词和必要限制。详细来源、命中记录、事实映射留在报告中，不混入客户可见文本。

QA交齐10条候选可记生成完成，保留人工审核待处理状态；候选生成与发布核实分别记录。只有本次请求范围内全部必需输出及检查均完成，且未引用过期资料时，`all_requested_complete` 才可设为 true。进度保存支持下一次继续，并不意味着对话结束后会后台运行。
