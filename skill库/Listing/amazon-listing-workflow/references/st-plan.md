# ST 规划与生成

用户只要求修改规则时保存规则，不自动重写Listing。要求生成ST时，按当前已有文案直接生成单行ST，不等待QA人工筛选或未来定稿；后续实际需要修改时，再生成新版并保留旧快照。

## 输入与候选建立

读取用户关键词库中的词根表（词语、关键词性、属性）、原关键词表、产品事实、品牌排除及违规词库，保留root_id、raw、原相关性标签、来源行与source_order。使用库内实际词根，不用竞品或自行扩词补齐；用户已标注的等级不自行改写。

先将关键词库中绝对精准等级的词根全部纳入初始候选，逐项检查，不只取几个高频词或沿用上版ST已选词。然后按以下六级顺序追加并排序完整候选池：

**绝对精准 ＞ 相对精准 ＞ 一般相关 ＞ 泛相关 ＞ 不相关 ＞ 未收录**

同级保持词根表来源顺序，无搜索量不虚构。“全部应用”在流程中体现为绝对精准全量进入候选并逐项处理；最终字符串还必须经过下述去重、事实检查和250字符上限，不是豁免这些检查。

## 对照已生成内容去重

在全量候选建立后，排查当前已有主标题、副标题、五点小标题及正文、长描述、QA实际Q/A，以及用户明确纳入的其他商品正文。QA有多少使用多少，不等人工筛选；未提供的分区记录为缺失。只用当前变体当前版本的目标语言正文。

排除内部报告、词库清单、竞品原文、旧版本、其他变体正文、审核标签、review_note、中文译文及HTML标签；这些不参与ST去重。未确认QA可参与实际文本重复检查，但不能作为产品特性的依据。

- 所有等级执行同一去重规则：词根已出现在当前已生成部分中即排除，包括绝对精准；ST内部也只出现一次。取消绝对精准重复豁免。
- 匹配用Unicode NFKC、忽略大小写并归一连续空白。拉丁词按词边界判断，避免词内误报；多词词根先按完整短语匹配。
- 明显单复数、词形和连字符差异另行核对并记录同根依据，不能借变形重复堆入；不把全部同义词自动视为同一词根。短语部分覆盖需逐词核对，不拆坏词根、不把部分命中伪称整条命中。
- 相同词根的不同来源先合并来源；等级冲突保留待核对，不擅自选最高级。记录每项排除命中的字段与片段。

按上述六级排序依次使用去重后仍适用的词根。明确不符合本品的颜色、尺寸、材质、无依据性能、品牌或违规词不得为填长度加入。不相关及未收录保留原等级和排位，仍需本品适配依据；排序不是强制每级都必须出现。无可用依据的候选记录原因，不凭空扩词。

## 拼接与字符限制

目标约240个字符，硬上限250个字符，包含全部实际空格及字符，按Unicode字符数统计。以用户这项字符规则为准，不采用此前450字符规则，也不采用UTF-8字节数或官方索引摘要作为本流程生成、裁剪与验收依据。

依六级顺序逐项加入完整词根，以一个半角空格连接，单行、首尾无空格，不添加逗号、分号、标签或编号。逐项计数，尽量达到约240；接近目标后不为了填满250追加无必要词。任何一次加入均不能超过250；当前项放不下时记容量不足并检查后续完整项，保留采用项的等级及同级来源顺序，不能截断单词。

如果去重后绝对精准本身已超过容量，按同级来源顺序保留能容纳的完整项，列出未容纳项；不得突破250或声称全部已入最终ST。若合适且未重复的词根不足约240，输出真实结果和不足原因，不重复回填、不加入不适用词凑数。

## 输出与记录

在双语HTML中输出当前实际ST、字符数（含空格）及单独的中文词义对照，按[HTML交付规则](html-delivery.md)。不输出平台字节摘要、UTF-8计数说明或已取消的标题公告引用。不把本地规则检查冒充平台上传校验。

内部保存initial_candidates（绝对精准全量及其他等级）、adopted、exclusions、dedup_scope、input_snapshot、missing_fields。采用项含root_id、raw、relevance、rank、source_order、source、fact_ids、repeat_policy=all_unique；排除项区分跨字段重复、ST内重复、事实不适配、品牌、违规词、等级冲突和容量不足。每个绝对精准候选必须能追溯到最终采用或具体排除原因。

检查六级顺序、全等级去重、事实适用、来源可追溯、单空格与len(text)≤250，报告实际字符数与约240目标的差距。不等待QA筛选，不用未来需要去重的说明代替本次ST。修改ST不自动删改前台文案。
