# 长描述规划

规划并按需生成能清楚回答购买问题的长描述。用户要求覆盖更多适用词根，允许与标题、五点重复；不得为去重删掉重要事实或限制，也不得为覆盖词根堆砌无意义文本。

## 输入与依据

读取产品信息表、适用型号/变体、已生成标题和五点、关键词/词根分配、竞品卖点及标题分析、品牌排除名单和违规词库。没有上文稿件时先独立规划，不假称已经比对。

本品表中明确、无冲突的数据可直接使用。竞品或其他参考资料中的本品新增主张需用户确认；竞品可以启发问题与表达结构，不能证明本品能力。用户给的护肤或型号比较例子是写作逻辑示例，不意味着本品就是护肤品或一定有多个型号。

首次处理 Alexa 相关要求时读 [购物问答依据](shopping-qa.md)。其公开功能支持问题、用途和比较导向的写法，但未提供保证抓取、排序或推荐的固定公式。

## 回答问题的组织方式

从实际产品和竞品分析中选出有依据的购买问题，依次说明：这是什么产品、适合谁、在什么场景用、解决什么问题、哪些参数支持其作用、如何选规格或使用，以及重要限制。

每个内容单元采用“客户问题或需求 → 直接回答 → 相关参数/功能 → 可证实利益 → 场景与限制”的逻辑，不要求每单元机械填满所有位置。参数只写有助决策的部分，必须说明对客户意味着什么；利益不能超出参数实际能支持的范围。

使用明确的产品名称、属性和对象，避免仅用“它”“更好”“高品质”等模糊指代。场景化表达解释在哪里、何时、由谁使用本品及其作用，不凭空扩展人群适用性或效果。

## 差异化与型号比较

对比竞品关注主题、表达遗漏和本品证实特点，选择可帮助客户区分产品的具体信息，记录本品依据及竞品来源。竞品未写不等于竞品没有；不得由文案遗漏推出本品独有、排名更高或性能更好。

型号比较仅在提供多个型号资料时进行，明确每种型号的真实差异、适用情境和限制。资料缺失时列问题，不虚构其他型号、竞品缺点或比较结论。对外文案不得引入其他品牌。

## 词根覆盖

尽可能使用绝对精准、相对精准、一般相关、泛相关四级词根，按此顺序优先覆盖。每个词根仍需符合本品事实、当前品牌与违规词规则。无关或冲突词不因覆盖要求而放行。

允许重复上文已出现的词根，不套用标题的最多两次规则。根词可以在自然句中承担产品、功能、人群或场景表达；避免把词根清单伪装为描述。词形变化、精确词根和仅语义覆盖分别记录，不伪称全部精确命中。

若容量不足，先保留关键事实、直接答案和必要限制，再覆盖高优先级词根。剩余词记录未用原因，不隐瞒覆盖缺口，不降低可读性硬塞。

## 格式与问答

长描述可使用自然段，也可按项目需要加入简短问答形式。用户未要求单段，不继承旧版单段限制。先核对目标站点、类目及描述字段允许的格式与长度；不将不支持的 HTML 或排版视为必需。

问题应来源于真实产品决策，回答先给结论再给依据，不为填词增加无意义问题。长描述中的问答会计入后续独立 QA 的已覆盖范围，不能在 QA 中换个问法重复交付。

这些是商家撰写的商品内容，不伪装成真实买家问答，不自动发布到社区问答或评论区。正文中不写“保证被 Alexa 抓取/推荐”等算法承诺。

## 输出与检查

规划输出：问题/需求、拟回答内容、场景、人群、功能、参数利益、fact_ids、竞品参考及词根分配。生成时另交付干净的长描述文本，分析与来源放在内部报告。

检查并报告实际字符数、当前适用字段限制、四级词根精确/词形/语义覆盖、未用词及原因、未决事实、品牌禁词检查状态。总词根与适用词根分母分别保留。不能把本地覆盖当平台收录或推荐证明。

沿用项目语言和工作目录，用户交付文件放 outputs。后续标题、五点或事实变化时，更新重复信息判断与 QA 已覆盖清单。
